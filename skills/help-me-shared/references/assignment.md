# 要求、证据与评分

## 来源与核验

清点任务书、rubric、公告、课件、图表、代码说明，完整阅读本次提供材料；扫描/复杂公式看原页。按文件/页码/题号记录已读与缺失，不把旧任务当本次要求。口头核验按 [Canvas](canvas.md) 匹配字幕和日期，记录时间戳。正式要求、口头补充、一般讨论和推断分开。

冲突先查版本、时间和明确修订，排除符号/适用条件不同。任务范围、指定方法、提交与考核优先老师明确要求；事实/数学错误不掩盖。决定范围或正确性的未解冲突先问，其他准备继续。

## 要求矩阵

使用[要求模板](../templates/requirements.md)；小任务简表即可。编号、来源、必做/选做、验收、文件与报告位置可追溯。摘要说清“做什么/交什么/怎么查”，默认展示后继续；只分析不实现。

任务含正式报告时，在提交规范和摘要中列明“LaTeX 工作源码 + 实际编译 PDF”。老师未指定格式或只要求 PDF 都沿用该约定；说明材料为 Markdown 不等于要交 Markdown 报告。真正不兼容的教师格式要求记录原文，按[报告路线](report.md)解决冲突；不能直接把报告目标改成 `.md`。

## 评分规划

使用[评分模板](../templates/rubric.md)。公开分值/权重才填写，未知就写未知；区分明确评分与改进建议，不猜隐藏测试或权重。

顺序：必做/硬限制/正确性 → 高权重证据 → 有价值的选做/对比/消融/误差/边界。不要把低权重美化放在遗漏必做之前。证据应容易定位，额外内容须服务目标。逐项查实际产物，不凭“看起来完整”评满分。

指定文献按[文献路线](literature.md)学习，其方法、约定和局限映射到本次实现，不能仅在参考列表装饰性引用。
