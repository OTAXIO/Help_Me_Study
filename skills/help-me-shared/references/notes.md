# 怎样把笔记写得详细又好懂

课堂和网络调研都读这份指南。课堂材料选择与确认步骤在 [class-learning-note](../../class-learning-note/SKILL.md)，调研与核验在 [online-research-note](../../online-research-note/SKILL.md)。这里只讲怎样写，让读者顺着问题学会，而不是看完一串概念名。

## 先把学习主线写成一串问题

从读者要理解或完成的事倒推。先写几个环环相扣的问题：前一问的结论，应当成为后一问的起点。删掉其中一节会不会让下一节看不懂？会，就留在主线；不会，考虑放批注或拓展。

例如讲二分查找，可以这样串：“顺序查找为什么慢 → 有序数组能帮我们排除什么 → 每次怎样排除一半 → 什么时候停止 → 为什么只需 O(log n) 次”。只列“定义、特点、应用”看不出知识怎样接起来。

入口页先用两三句话讲共同问题，再给阅读路线：

- 最短主线具体到页与节，按依赖排列。
- 对照内容说明拿什么与什么比较、为什么要比较。
- 做练习或操作前先读哪里，哪些拓展第一遍可跳过。
- 按下表说明批注的颜色、文字类别和阅读顺序，让读者知道哪些先读、哪些第一遍可跳过。符号较多时列“符号 / 含义 / 条件”，同名不同义单独提醒。

每页开头用一两句话定位：它接着哪一步、读前要会什么、先读哪几节，其余什么时候读。不要先寒暄。小节标题写成要回答的问题或要做的事，例如“每次排除一半，为什么不会丢掉答案”。只看标题也应能复述主线。

## 一节怎样从问题走到能用

默认按下面的顺序讲，简单处可以合并，不机械复制这些标签当标题。

1. 说出要解决的问题。读者先知道为什么学它。
2. 给最小设定。术语、符号先定义，交代维度、单位和适用条件，只引入这一步会用的东西。
3. 推导或操作。每步写出原因，说明凭什么能从上一行走到下一行。读者可能问“这是什么”“为什么要学”的位置，就地解释。
4. 给能手算或当场验证的小例子，写出核对。代码的输入和输出与例子一致，预期结果与实测结果分开。
5. 指出结论后面用在哪。让下一问有来由。
6. 需要图时，把图接在它解释的段落后，不机械等到节尾。

一个中性例子：在有序数组 `[2, 4, 6, 8, 10, 12, 14]` 中找 `10`。先看中间的 `8`。因为数组递增且 `10 > 8`，答案只可能在右侧 `[10, 12, 14]`。再看 `12`，因为 `10 < 12`，只剩 `[10]`，第三次找到。核对：检查了 `8、12、10` 三个值；每次排除的部分都不可能包含目标。这个例子为后面“每次把候选数约减半”提供依据。若要写一般最坏比较次数，应另说明非空数组、端点约定和取整；不要仅凭这个例子当作证明。

用户追问后要求补充时，先找到第一次用到该概念的位置，把定义或解释放在它前面，再调整后续称呼和引用。不要把所有补充堆到页尾，让读者读到一半才发现前提藏在后面。

## 哪些放正文，哪些可以先跳过

正文保留理解下一步必需的定义、理由和例子。Notion 的 callout 使用下表的固定颜色，并保留文字类别。本地 Markdown 用带相同文字类别的引用块，入口页的阅读路线也说明这套读法。

| Notion 颜色 | 文字类别 | 内容与第一遍读法 |
|---|---|---|
| 蓝色 | 一句话 | 本页核心直觉，继续前先读懂 |
| 黄色 | 易错提醒 | 会导致误用的条件或操作风险，第一遍要读 |
| 灰色 | 严谨性与延伸（第一遍可跳过） | 不影响当前步骤的证明限定、边界和额外背景 |
| 红色 | 结论限制（必须先读） | 会推翻或限制本页结论的内容，例如对整个研究方向提出质疑的论文，读主线前先看 |

蓝色帮助抓住直觉，黄色帮助正确使用，灰色内容可以稍后读。红色只用于会推翻或限制本页结论、必须先读的依据，读者应先据此确定后续结论适用到哪里。

决定当前公式能否成立的条件写进正文或黄色易错提醒。涉及本页结论整体有效性的限制用红色。更长的推导与进阶例子放必要拓展子页，从正文说明何时再读。主线在当前页保持连续，不为每个术语拆一页。

## 图要回答哪个问题

写完一页后，回头检查每个主要小节。凡是涉及空间或结构关系、流程、多对象对比、随时间或参数变化的地方，默认配一张图。先用一句话明确它回答什么问题，再选图形。方向调研还常需要全景图、时间线、数量或指标对比图。

一页完全没有图时，回看是否遗漏了这些关系。只有内容确实都能用简短定义、一步计算或对照表清楚表达，才决定不配图，并在工作记录中简短说明理由。这样能在交稿前发现整页漏图。

一张图只讲一件事，直白优先。紧跟相关解释；图注先告诉读者看哪里、箭头或轴表示什么，再说能得出什么。自绘图使用正文例子同一组数字，代码也沿用它。例如上面的二分查找图可以逐行画出七个数、剩三个数、剩一个数，用划去区域回答“哪些数为什么被排除”，不要换成另一组数。

数量图写清样本范围，指标图保持可比条件。自绘图的脚本生成、源文件保留、导出与最终嵌入尺寸检查，以及图片来源和排版，统一按 [formatting.md](formatting.md) 的“图形”一节执行。

## 对照表怎样帮助做判断

比较三个及以上对象时用表。列选读者真正要比较的维度，例如“方法 / 核心做法 / 代价”或“论文 / 时间与出处 / 做了什么 / 报告的结果”。每行填相同的列，采用一致的口径和单位，未知项写明缺口，读者才能横向比较。

表后用一两句话指出看完应得到什么判断，例如哪种方法更适合当前约束、主要代价是什么、还缺什么证据。这个判断应能从表里的信息得到。表格的排版和转换检查按 [formatting.md](formatting.md) 的“表格”一节执行。

## 语言怎样让读者少卡一步

短句、陈述句，一句只说一件事。先给问题或结论，再给理由，读者才知道细节在解释什么。把术语翻成日常词，但保留准确名称；第一次出现就定义并带条件、维度或单位，避免靠猜。相同符号换了含义，当场点破，不让读者套用上一页的意思。

因果词落到具体依据：“原因是数组有序”“所以左侧都小于目标”“这就是下一节估算次数的依据”。不用“值得注意的是”“众所周知”“综上所述”代替解释，也不靠排比或抒情增加篇幅。“直白地说”只用于把难定义翻成人话，每个难点最多一次，翻译完继续推理。

例子选能手算的小数字，核对不是一句“显然正确”，而是展示可检查的等式、输入输出或条件。说明没证明什么、结论只覆盖哪些数据、哪些材料没读全文、哪些操作没跑，读者才知道可以信到哪一步。

下面是自己编的小例子。对照的重点是补齐理由，不是换一批漂亮词。

| 不这样写 | 这样写 | 为什么 |
|---|---|---|
| 众所周知，二分查找高效，复杂度为 O(log n) | 每次比较后，候选区间约缩小一半。经过 k 次，规模约为 n/2^k。让它降到 1，需要约 log₂n 次，所以最坏时间为 O(log n) | 把结论中省掉的因果链写出 |
| 设置步长 η 即可迭代 | 步长 η 是每次沿更新方向移动的比例。若当前值为 6，方向为 −2，η=0.5，下一值为 6+0.5×(−2)=5。核对：确实向负方向移动了 1 | 先解释符号，再让数字验证含义 |
| 该方案性能优越，值得采用 | 来源在所列测试集上报告耗时降低；我没有复现。你的输入规模不同，先测一次同条件耗时，再决定是否采用 | 区分来源结果、核验范围与行动判断 |

标题不加句号，不用突兀的“(5)”括号编号。不写自我介绍或“下面我将为你”，直接进入问题。笔记里的“我”只用于“我的判断”“我没有复现”等责任说明。句子短不等于解释少；省下套话，把空间留给原因和例子。

## 怎样收尾并判断详细程度够不够

页尾放理解检查。问题和答案相邻，答案优先放可展开块；目标不支持折叠时另行写“答案”，留出先想再看的机会。题目检查能否解释原因、手算一步或识别误用，不只背定义。

再给“继续学习”：下一步具体读哪页哪节、为什么现在读、会用到本页哪个结论。调研的建议与风险按调研入口组织，不在这里重复一份。

默认细到读者能跟着推导、亲手算例子或照着完成操作。交稿前顺着标题读一次，再假设只会页首声明的前置知识，逐步检查：每个新词是否已定义，每步是否有原因，例子是否真核对，下一步是否有来由。骨架式的概念罗列达不到这个程度。详细是填上理解缺的台阶，不是多列概念或重复结论。
