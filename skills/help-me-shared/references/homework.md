# 作业实施与未压缩交付

开始前复用已核验的要求与评分矩阵，补齐 [要求流程](assignment.md)，展示摘要；无关键歧义继续。创建目录见[运行工具](runtime.md)，原资料保留，所有新增代码/配置、报告/图表、结果、来源和 QA 在工作目录。

## 实施

- 数学：给关键假设、公式、完整推导和必要独立核算，不能只有答案。
- 编程：真实代码、指定接口、相关边界、可复现运行说明；不虚报使用配置/模型。
- 实验：保留真实环境、参数、输入/输出、日志和数据；报告与实际结果一致。
- 复现：先学指定文献，说明原文/课程/本次设置及偏差，不用简化实现冒充完整原方法。
- 覆盖必做和高权重后，再有目的地补对比、消融、误差和局限，不造结果或追求无关篇幅。

报告读[报告路线](report.md)与[排版](formatting.md)，正式报告必须有完整 LaTeX 源码及实际编译的 PDF；Markdown 只作内部草稿/记录，不能代替交付。先在要求摘要中列出该格式，编译受阻据实标记未完成，不自行降级。验证读[验收](verification.md)。正式文件自然准确，去除助手自述、聊天、内部 QA 和无关日志；事实、来源、必要声明保留。

## submit 与三种不同操作

1. **整理**：复制老师要求的正式文件到 `submit/`，命名/结构按要求，保留未压缩文件与目录。报告须先满足 LaTeX 源码与编译 PDF 的完成条件，默认放最终 PDF，源码是否也放入按提交要求；不能用 `report.md` 充数。用户已明确改格式时采用该决定。完整代码是否提交按老师要求，工作日志/来源缓存/内部评分表不随意放入。
2. **打包**：只有用户明确要求打包/压缩后创建 ZIP/7z/tar 等归档。老师要求 ZIP、课程全部完成、Overleaf 源码需求都不足以自动授权。未授权先备源目录，标“待用户指令后打包”。获授权后检查归档内容、CRC/完整性及解压后的可用性，不把整个 work 无差别打包。
3. **课程提交**：只有用户明确要求提交才通过指定系统上传。打包不等于已提交，完成文件也不等于上传授权。

此边界适用于所有最终提交包和 Overleaf 包。本套件不提供自动打包脚本。未压缩也检查实际文件、引用路径、运行、PDF 显示。

交付列路径、覆盖、实际测试/显示检查、缺口，分别说已编写/运行/编译/导出/视觉查/整理/打包/提交。默认结语状态为“提交材料已整理并检查，尚未打包”（未检查则据实改写）。
