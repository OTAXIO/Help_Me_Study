# 交付验证

按影响选择必要检查：不因简单排版写无效测试，也不省略真实计算/接口/边界/渲染。

| 对象 | 实际证据 |
|---|---|
| 要求/评分 | 每条公开必做/权重对应产物与验证，未知不编造 |
| 文献 | 实际阅读范围、方法与实现、差异处理、真实引用 |
| 数学 | 条件、推导、关键例子独立核算 |
| 代码/实验 | 实际入口、配置、输入输出、相关边界，报告一致 |
| 报告 | 源编译、PDF 导出、每页视觉，分别记录 |
| Notion | 父页及所有变更子页回读、资源/层级保留；显示另验 |
| submit | 命名、格式、仅正式材料、路径与源码可用；默认未压缩 |
| 归档 | 仅明确打包后创建，再检查内容/完整性和解压可用性 |
| 演讲 | 风格/时长/听众目标先确认，页序主线、人称贡献/时间、估时与试讲区分 |
| 报告逻辑 | 项目问题、每个实验目的与对照、并列/依赖/因果关系、大节递进与段落承接 |
| 笔记格式 | [格式检查](format-validation.md)：源结构、目标节点/样式、内容资源完整、最终显示分别核验；无真实页面不声称已修页面 |

检查失败先修复，修复后重验受影响部分，未做项目标未验证。不得用“文件存在/编译成功/API 接受”替代端到端证据。

交付报告简洁说：文件/页面位置、覆盖、实际测试与视觉检查、尚缺、是否已同步/打包/提交。完成材料与上传课程系统分开。
